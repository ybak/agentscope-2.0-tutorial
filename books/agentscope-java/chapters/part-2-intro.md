---
title: 第二篇 核心构建块
source: 新写
---

跑通第一个 Agent 之后，真实业务会马上追出一串问题：Agent 该直接用底层的，还是用封装好的？界面要边生成边显示，数据结构长什么样？模型想换成公司指定的（或内网自建的），要动哪些东西？Agent 凭什么去操作订单、工单这些业务系统？用户隔天回来，会话怎么接着聊？想给所有 Agent 统一加日志和追踪，又不想改框架代码，插在哪里？哪些操作必须交给人拍板？本篇用七章逐一回答——这七章正是第一篇概念地图中央的七个核心构建块（组装 Agent 所需的基础组件），下面逐一拆开。

第 4 章讲 Agent 与 ReAct 循环：直接用 ReActAgent 还是 HarnessAgent、三种调用入口怎么选、实例生命周期怎么管。第 5 章讲消息与事件：为什么流式界面依赖事件流而不是只等一个最终返回，以及事件如何还原成完整消息。第 6 章讲模型接入：接自己的模型、切换供应商、走 OpenAI 兼容网关的做法。第 7 章讲工具：让 Agent 操作你的业务系统，既包括自己写工具，也包括接入现成的工具生态。第 8 章讲上下文：会话状态放在哪里、如何在实例与机器之间延续。第 9 章讲中间件：不改框架代码，在执行链上插入横切逻辑。第 10 章讲权限系统与人工介入：为“哪些操作要人审批”划出可配置的边界。

这七章彼此咬合：Agent 是循环的骨架，模型与工具是循环的两端，消息与事件是流转其间的数据载体，上下文决定状态放在哪里、如何延续，中间件与权限系统则分别从“扩展”与“约束”两侧塑造循环的行为。建议按章节顺序阅读；已经熟悉某个构建块的读者也可以直接跳到对应章节，各章内容相对自成体系。

读完本篇，你就能脱离示例代码，用第一性的视角理解 Harness 的各项能力分别挂在循环的哪个位置——这也是进入第三篇（第 11 章起）深入 Harness 工程能力之前需要的准备。
