# 第 1 章 初识 AgentScope 2.0

> 本章导读：当你想让自己的应用从“调用一次模型、返回一段文本”，升级为一个能查业务数据、连续执行多步任务、需要时向你确认再继续的智能体时，先别急着写代码——本章先回答“AgentScope 适合构建什么样的应用”，再拆解 Harness 支撑 Agent 持续工作的三个维度。读完本章，你会知道这套框架适合解决什么问题、能力边界在哪里，后面几十章各自对应地图上的哪一块。

## 用 AgentScope 能做什么

第一类是问答与助理场景。对于客服、知识问答和业务助理，你可以让 Agent 结合会话历史、检索结果和实时业务数据回答问题，并通过工具查询订单、更新工单或调用已有系统。前端既能展示回答，也能展示正在调用的工具和需要用户处理的待办。

第二类是多步骤任务场景。对于调研、数据分析、代码修改这类任务，Agent 可以在工作区中读取材料、制定计划、执行工具并生成文件；涉及不同专业能力时，再委派给子 Agent（Subagent，接受主 Agent 委派、独立完成一块子任务的下属 Agent）。长任务积累的上下文、用户中途补充的要求，以及暂停后继续所需的状态，都有对应的管理机制。

例如，一个“整理客户反馈并生成改进报告”的 Agent，可以先读取资料和团队规范，调用业务工具核对数据，让子 Agent 分别分析不同产品线，最后生成报告。用户可以在过程中补充关注点，在发送报告前确认，也可以离开页面后再回来查看进度。**Harness 将这些步骤需要的运行能力组合起来，让开发者集中定义业务目标、工具和执行边界。**

## Harness 如何支撑 Agent 持续工作

看完“能做什么”，再看“靠什么做到”。ReAct 的“推理、执行工具、观察结果”循环是 AgentScope Harness 的基础。`ReActAgent` 提供推理、工具、权限和中间件（Middleware，请求链上的横切拦截器）等能力，`HarnessAgent` 在同一循环上组合工作区、上下文与会话管理，围绕下面三个维度支撑持续执行。推荐从 `HarnessAgent` 开始，再按场景配置所需能力；具体组合见第 11 章。下面三小节各对应一个维度：任务怎么持续跟进、上下文怎么管理、工具怎么受控执行。

### 持续跟进长程任务

处理代码修复、调研等多步骤任务时，可以启用 Todo（内置任务清单工具，Agent 用它记录步骤与进度）跟踪进度，结合 Plan Mode（计划模式）先调查、写计划，经用户确认后再执行；独立工作可委派给子 Agent，同步等待或在后台完成。计划、待办和子任务各有状态，后续执行能够继续跟进未完成的工作。有明确验收标准时，应用还可以记录任务要求与实际验证结果，为下一步提供依据。

这套持续跟进能力有两条数据支柱：Session Log（会话日志）保存消息、工具调用与交互过程，checkpoint（状态快照）保存继续工作所需的状态。需要后台执行、忙时排队、补充要求或中断续做时，使用 `AgentSession`（会话操作入口，负责提交任务与安排后台执行）管理任务；前端则从日志补齐已有进度，再接收新增事件。详见第 17 章（计划模式）、第 16 章（子 Agent）和第 19 章（会话操作与恢复）。

### 管理上下文，控制模型能看到什么

Harness 在每次请求模型前，重新组织稳定指令、对话历史、当前任务状态和参考材料。工作区提供项目规则、记忆、知识与 Skill（技能，以 Markdown 文件描述、按需加载的能力包），动态来源按轮次补充最新业务事实；应用可以配置内容来源、优先级和预算，让本轮输入围绕当前工作展开。记忆和外部材料作为参考资料，业务数据的读取权限仍由应用校验。

随着任务变长，Harness 将过大的工具结果保存到文件，按预算选择材料，并通过结构化压缩保留目标、关键发现和下一步。模型使用精简后的工作上下文，完整执行历史仍保留在 Session Log 中；跨会话的信息则由长期记忆承接。详见第 13 章（上下文管理）、第 12 章（工作区）和第 14 章（记忆）。

### 让工具受控、安全地执行

Java 工具和 MCP（Model Context Protocol，模型连接外部工具的标准协议）将模型的行动请求连接到文件、代码与业务系统。应用配置可用工具，权限系统再根据规则、运行模式和具体参数，决定允许、拒绝或请求用户确认。需要人工审批或外部系统执行的操作，可以保存待办、等待结果，再继续推理。

执行代码和命令时，可以配置 Docker 或远端沙箱，并选择按用户或会话隔离的范围；实际文件、网络和资源边界由工具实现与执行后端落实。工具调用、结果和审批过程通过类型化事件（每类事件对应一个明确的 Java 事件类型）与会话日志供应用展示和追踪。详见第 7 章（工具）、第 10 章（权限与人工介入）和第 18 章（沙箱）。

到这里，框架的轮廓已经清晰：能构建两类应用，靠三个维度支撑持续工作。第 2 章就把其中最小的一条线——创建 Agent、两轮问答、流式输出——真正跑起来。
